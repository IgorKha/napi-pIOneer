# AI и продолжение фазы 3

AI доступен в редакторе проекта во вкладке **AI** и в редакторе скрипта по кнопке **AI**.
Настройки разделены на MQTT, AI и Секреты; прямые ссылки: `#/secrets/mqtt`, `#/secrets/ai`, `#/secrets/secrets`. Настройки → AI: OpenAI,
Anthropic или совместимый Chat Completions endpoint; модель, effort, общий лимит
выходных токенов, встроенный поиск или SearXNG. Ключ записывается только в SecretStore.
История каждого проекта — приватный JSONL в `data/chats`, новый чат удаляет историю.

Помощник читает плату, схемы нод, текущий граф и журнал. `propose_ops` проверяет пакет
и показывает предпросмотр; **Принять** отправляет обычный пакет с исходной ревизией и
undo. Устаревшее предложение требует нового ответа. Помощник сам не запускает граф,
не управляет GPIO/перезагрузкой/секретами. Черновик блока — текст с AST-проверкой;
импорт кода в worker происходит только после пользовательского «Проверить и сохранить».
Ссылки на ноды/пины фокусируют канвас. Ответы идут потоком, есть остановка, usage и ссылки.

На Linux официальный SDK работает в отдельном процессе на один запрос. Одновременно
разрешён один AI-ответ; у процесса лимит адресного пространства 128 МиБ, сниженный
CPU-приоритет, сетевой таймаут и общий таймаут чата 240 с. После завершения/отмены процесс
закрывается. Превышение лимита завершает ответ ошибкой, не переносит SDK в память core.
На Mac SDK работает напрямую. Версии зафиксированы, aarch64/cp312-зависимости вендорятся
отдельно от системного FastAPI/Pydantic. Модель запускается у провайдера.

Веб-страницы недоверенные. `web_fetch` запрещает локальные/служебные адреса, повторно
проверяет редиректы и подключается к проверенному IP; размер ограничен. PDF этот
инструмент не извлекает. Встроенный поиск провайдера даёт ссылки на даташиты.
Anthropic проверен контрактными тестами; для живой проверки нужен его ключ.

## Графы и состояние

Экспорт JSON в редакторе, импорт в списке проектов. Импорт создаёт новый остановленный
проект, без автозапуска и восстановления состояния. Группы разворачиваются; пользовательские
блоки нужно перенести через CodeTree ZIP отдельно. Лимит JSON 1 МиБ, 500 нод/2000 связей.

«Сохранять состояние» выключено по умолчанию. Восстанавливаются только Toggle/Counter/Latch,
с совпадающим типом, параметрами и inline-входами. Таймеры, события и аппаратные handles
не сохраняются. Контрольная точка каждые 10 с и при нормальной остановке, атомарная запись
только при изменении; внезапное отключение может потерять последние 10 с. Восстановленный
Bool может сразу включить связанный выход — включайте опцию сознательно.

## Оверлеи

Другие функции пина → предпросмотр: diff фактического `/boot/uEnv.txt`, hash, наличие `.dtbo`
и владельцы затронутых ресурсов. Запись требует галочки подтверждения и актуального hash.
Сохраняется приватный бэкап, заменяется только строка `overlays=`; остальные строки сохранены.
После записи интерфейсы вступают в силу после отдельно подтверждаемой перезагрузки.
На стенде перезагрузка запрещена. На реальной плате boot-файлы в автоматических тестах
не меняются: проверены операции на временных файлах и только чтение конфигурации платы.

## AI в редакторе скриптов

У каждого скрипта отдельная история, независимая от чатов проектов. Помощник может
читать дерево файлов, текстовые файлы до 64 КБ, состояние платы и последние 100 строк лога.
Python-файлы предлагаются через `draft_file`: проверяется только синтаксис, код не исполняется.
Кнопка «Редактировать» открывает редактируемый diff с исходным файлом; «Сохранить файл»
сравнивает SHA-256 исходника под общей блокировкой CodeTree, отклоняя устаревшие предложения.
Можно предложить новый файл во вложенной папке. Сохранение через AI не вызывает
`restart_on_save`; запуск и перезапуск остаются отдельными действиями. Несохранённые
правки редактора сохраняются перед отправкой сообщения и принятием предложения.
Ключ провайдера и секреты в контекст модели не передаются. Один SDK-процесс и общий
лимит запросов действуют одновременно для чатов проектов и скриптов.

Это помощник при написании скриптов; программный вызов модели из исполняемого Python
через SDK скриптов пока не добавлен.

Проверка расширения 2026-10-11: 241 backend-тест и сборка фронтенда прошли.
В браузере проверены разделы настроек, отдельная история скрипта, просмотр и
сохранение файла без запуска. Реальный OpenAI-запрос на Napi-C выполнил
`get_script → read_file → draft_file`; после явного принятия сохранён
`print("AI script live OK")`, скрипт `466180f2` остался остановлен, MQTT подключён.
Запрос занял 70,6 с; во время запроса оставалось около 78 МБ доступной RAM.

## AI в редакторе кастомных блоков

В «Мои блоки» есть кнопка «AI-помощник» и отдельный чат `block:<id>`.
Помощник читает метаданные, схемы нод и файлы только выбранного блока через
`get_block`, `read_file`; `draft_file` создаёт предложение, ничего не записывая
и не исполняя. Доступны описание платы и каталог типов нод, но отсутствуют
инструменты изменения графа, запуска и чтения чужих скриптов.

Пользователь открывает diff и может редактировать предложение перед сохранением.
Принятие сравнивает SHA-256 исходного файла под блокировкой, сохраняет именно
текущий блок и выполняет штатную проверку/обновление схемы. Новый блок не создаётся.
Как при обычном сохранении, ошибка схемы сохраняется в метаданных и старая схема
остаётся в палитре; ошибка показана редактором. Проверка импортирует описание
в отдельном процессе; ноды и проекты не запускаются. Несохранённые правки
сохраняются перед отправкой и принятием; изменённый исходник требует нового предложения.
