# Изображение → HTTP → результат

ESP32-CAM/Snapshot/MJPEG отложены пользователем 2026-10-11 и будут сделаны отдельно.
Текущий сценарий использует обычный HTTP(S) endpoint с PNG/JPEG, без камеры.

## Ноды

- **Изображение по URL** (`builtin.image_url`): по «Получить» скачивает до 2 МБ,
  устанавливает Image и выдаёт «Готово». Один запрос одновременно, таймаут 0.5–60 с.
  URL может ссылаться на секрет. PNG/JPEG определяются по сигнатуре; декодирование,
  ресайз и проверка всех внутренних структур формата не выполняются.
- **HTTP: обработка** (`builtin.http_process`): POST с сырыми байтами изображения
  (`image/png` / `image/jpeg`) либо с JSON. Весь JSON-ответ выходит на «Ответ»;
  «Число» извлекается по пути `value` или, например, `result.score`.
  «Число найдено» отличает отсутствующее поле/Bool от числового нуля.
  «Успех» требует HTTP 2xx и корректного JSON; ошибка не выдаёт «Готово».
  JSON-запрос/ответ — максимум 256 КБ. Multipart/base64 не используются.
- **Сохранить изображение** (`builtin.save_image`): по событию сохраняет Image
  в `data/images/<id проекта>/<uuid>.png|jpg`, выдаёт относительный путь и «Готово».
  На ноде доступна ссылка скачивания. Лимит 100 файлов / 50 МБ на проект,
  без автоматического удаления или перезаписи. Очистка пока через SSH;
  удаление графа тоже не удаляет его снимки.

PNG/JPEG не передаются через WebSocket: live содержит только размер. Превью получает
последнее изображение из памяти графа отдельным API, защищённым пользовательской
сессией. Сохранённые файлы скачиваются через такое же защищённое API. Новых библиотек
для изображений или HTTP не требуется. Передача Image в worker Python-блоков пока
не поддерживается; цепочка использует встроенные ноды.

Все сетевые/дисковые операции выполняются вне потока движка. При загрузке ошибка
очищает Image; ошибка обработки сбрасывает число/флаг найденного значения.
Автоматических повторов POST нет, чтобы не дублировать побочные эффекты обработчика.
Длительная работа сохраняет origin и контекст исходной команды.

## Тестовый сервер

```bash
python3 tools/media-test-server.py --port 8099
```

`GET http://127.0.0.1:8099/image.png` отдаёт сгенерированную шахматную PNG 64×64;
`POST http://127.0.0.1:8099/process` принимает изображение или JSON и возвращает
`{"ok":true,"value":42,...}`. Это тестовый обработчик, распознавания в нём нет.
Для платы адрес должен быть доступен **с платы**, а не только из браузера.
Запущенный на плате сервер можно оставить на `127.0.0.1`; для сервера на другом
компьютере укажите `--host 0.0.0.0` и его LAN-адрес в параметрах нод.

Граф: «Кнопка (пульт)» Клик → «Изображение по URL» Получить;
Изображение → HTTP: обработка Изображение и Сохранить изображение Изображение;
Готово → HTTP: обработка Отправить и Сохранить изображение Сохранить;
HTTP: обработка Число → Watch. Для действия по результату подключайте «Готово»,
а не только числовой выход: число сбрасывается при начале нового запроса.

## Проверка

`backend/tests/test_media.py`: настоящая HTTP-цепочка Image/JSON, секретный заголовок,
сохранение байтов, origin, ошибки HTML/размера/таймаута/HTTP, числовое поле,
квоты/пути/симлинки и авторизация превью/скачивания.

2026-10-11 установлено на Napi-C. Полный набор: 216 тестов; сборка фронтенда прошла.
В браузере проверены реальное превью 64×64, результат 42 в Watch и ссылка скачивания,
ошибок в консоли нет.

На плате оставлен граф `57d5ff47` — «Изображение → HTTP → MQTT (тест без камеры)»,
автозапуск выключен: после деплоя/перезапуска сервиса нажмите «Запустить» в редакторе.
Команда `smoke.image` без аргументов через домашний MQTT запускает
PNG → HTTP → JSON, сохранение и событие `smoke.image.changed`. Пример запроса в топик
`pioneer-test/napi-silverrhinoceros/cmd/smoke.image`, QoS 1, без retain:

```json
{"id":"image-demo-001","args":{},"ttl_ms":5000}
```

Ответ приходит в `pioneer-test/napi-silverrhinoceros/resp/smoke.image`, результат содержит
`value: 42`, `content_type: "image/png"`, `bytes: 209`. Состояние —
`state/smoke.image.value`, событие — `event/smoke.image.changed` под тем же префиксом.
Новый запуск требует нового `id`. На плате проверены реальная MQTT-команда/ответ,
событие, HTTP POST, превью и скачивание сохранённого файла (байты совпадают).

Тестовый сервер на плате работает как **временный** `pioneer-media-test.service`,
слушает только `127.0.0.1:8099`. Он не включён в автозапуск ОС. После перезагрузки
для ручного запуска стенда выполните через SSH:

```bash
systemd-run --unit=pioneer-media-test \
  --property=WorkingDirectory=/mount/rfs/rw/.pioneer/app \
  --property=Restart=on-failure \
  python3 tools/media-test-server.py --port 8099
```

Остановка сервера: `systemctl stop pioneer-media-test`; сам граф останавливается
обычной кнопкой «Стоп». GPIO и физическое реле в этой проверке не использовались.

При UI smoke найден и исправлен цикл GET `/projects/<id>/live`: callback
`resetProjectLive` теперь стабилен между рендерами. После обновления UI снимок
получается при открытии графа; новый запуск цепочки обновляет UI через WebSocket
без повторных live-запросов (проверено по журналу HTTP).
