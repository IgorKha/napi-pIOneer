## Исправления (по серьёзности)

### Критично

1. **ABBA-дедлок при правке загрузки.** `kernel_drivers.apply` берёт `drivers.lock → overlays.lock` (`kernel_drivers.py:254`), `pulls.apply` — `overlays.lock → drivers.lock` (`pulls.py:63`). Одновременные apply DHT22 и подтяжки → оба потока висят навсегда, все preview/apply оверлеев тоже. → единый порядок локов; лучше — п. 9.
2. **Удалённая команда остановленному проекту отвечает `ok: true`.** `Engine._submit` при отсутствии рантайма ставит `ctx.done=True` без колбэков → `execute_command` ждёт весь таймаут и отвечает 200 `{"ok": true}` (`remote.py:80`; то же в `api/hooks.py:63`). → в `_submit` вызывать отдельный путь «отклонено» (например `ctx.rejected = "проект не запущен"` + on_complete), транспорт отвечает ошибкой 409/503 сразу.
3. **Остановка/падение скрипта включает реле с активным LOW.** `_Runner._wait` → `hw.release(owner, safe_value=False)` всегда пишет LOW; у `sdk.Output` нет безопасного уровня (`sdk/__init__.py:112`). → `Output(pin, initial=False, safe=False)` (или `active_low=True`), core запоминает safe-уровень при `acquire` и использует его при release/stop/crash и при остановке сервиса. Обновить докстринг и справку.

### Важно

4. **Один файл > 5 МБ ломает проект.** `CodeTree.files()` кидает TreeError, а его вызывают write/mkdir/delete/import (`codetree.py:79`) и `ScriptManager.delete` (`scripts.py:323`). Скрипт-логгер, пишущий CSV в cwd (= корень проекта), делает проект нередактируемым и неудаляемым. → большие файлы показывать в дереве с пометкой (без хеша), лимит 5 МБ — только на upload/write через API; delete работает всегда; подумать о `data/` каталоге проекта вне лимитов или о рекомендации писать данные в `pioneer.sdk.data_dir()`.
5. **Неожиданное исключение в RPC вешает скрипт навсегда.** `_Runner._rpc_loop` ловит только узкий набор исключений (`scripts.py:152`), иначе поток RPC умирает, а `_Client.call` ждёт без таймаута. → ловить `Exception` (с логом), отвечать ошибкой; в SDK — таймаут на `call` (кроме заведомо долгих, например `uart_read` с timeout).
6. **Долгий старт проекта → 500, но проект запущен.** `Engine.call(timeout=10)` в `start_project`; `TimeoutError` не ловится в `ProjectManager.start` (`projects.py:240`), а старт продолжается в потоке движка. → для старта/стопа не использовать короткий таймаут (или ждать без таймаута с прогрессом), ловить TimeoutError, статус выставлять по факту.
7. **Watchdog: одна медленная проверка здоровья = перезагрузка платы.** Любое исключение в `_feed` (включая `wait_for(…, 5)`) навсегда прекращает кормление (`watchdog.py:62`). → перезагружать только после N подряд неудач / суммарного времени без здоровья, транзиентный stall движка пропускать.
8. **Зависимости проекта нельзя поменять или удалить.** После первой установки любое изменение `requirements.txt` → 422, API удаления нет; при удалении скрипта/блока `data/dependencies/<kind>-<id>` остаётся (`dependencies.py:30`). → переустановка в новый stage + атомарная замена (скрипт остановлен), удаление site-каталога вместе с проектом.

### Архитектура / эффективность

9. **Три независимых писателя `uEnv.txt`** (`overlays.apply`, `kernel_drivers._commit`, `pulls.apply`) — каждый со своими хеш-проверкой, бэкапом, атомарной записью, откатом, правами и порядком локов (`overlays.py:73`). → один сервис `UEnv` (один лок, один формат бэкапа, один откат), остальные строят план и отдают ему.
10. **Каждое сохранение хеширует весь проект.** `CodeTree.write()` → `files()` читает и sha256 все файлы до 50 МБ; `import_zip` пишет по файлу → O(n²) (`codetree.py:101`). → для лимитов — `stat().st_size`, хеши только для `GET tree`/CLI.
11. **`_commit` ядерного драйвера держит `hw._lock` и `res._lock` во время fsync-записей** (`kernel_drivers.py:262`) — стопорит все acquire/release/UART. → под локом только проверка захватов, запись — после, с повторной проверкой хеша.

### Надёжность / мелочи

12. **Дедупликация команд по `id` не атомарна** (`remote.py:51`): две одновременные доставки одного `id` (QoS1-повтор) выполняются обе. → помечать id «в работе» до inject.
13. **Webhook читает всё тело до проверки размера и принимает токен в `?token=`** (`api/hooks.py:45`): 50 МБ тела в RAM; токен — в access-логе nginx. → читать потоком с лимитом (как `limited_body`), токен только заголовком (или query-вариант помечен как небезопасный в доке ноды).
14. **Неудачное повторное открытие пина снимает существующий захват владельца** (`hw.py:76`). → освобождать только если захват был создан этим вызовом.
15. **Стиль новых модулей** (`dependencies.py`, `pulls.py`, `watchdog.py`, `api/watchdog.py`, `language_service.py`, `ModulesPage.tsx`): однострочники через `;`, `try:return …` — особенно опасно в коде, который правит загрузку. → привести к стилю остального кода (форматтер в `make lint`).
