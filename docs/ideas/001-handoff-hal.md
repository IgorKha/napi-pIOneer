# Заметка для рабочего чата: доработки HAL под модули и стенд

Контекст: [001-modules-and-simulation.md](001-modules-and-simulation.md). Сама фича — позже, но эти решения дешевле принять **сейчас**, пока HAL маленький (`backend/pioneer/hal/`: GPIO + ADC, `MockHAL` с `set_level`/`wire`/`set_adc`).

## Что сделать

1. **Шины в HAL.** Добавить в интерфейс `HAL` абстракции `I2CBus` (по номеру шины; транзакции read/write/write_read, адрес на операцию), `SPIDevice` (bus, cs, mode, speed; xfer), `UARTPort` (open/read/write/baud) + PWM-выход как отдельный тип линии (soft-PWM уже есть). Реальные реализации — `smbus2` / `spidev` / `pyserial` (все уже стоят на плате).

2. **MockHAL → стенд (Bench).** Вместо ручных `set_level`/`wire`/`set_adc` — реестр **моделей устройств**, подключённых к ресурсам:
   - модель подписывается на изменения выходов (GPIO-out, PWM duty) и на транзакции шины по своему адресу/CS;
   - модель может сама выставлять входы (GPIO-in уровни/фронты, напряжение на ADC-канале) и отвечать на чтения шины;
   - модель отдаёт своё состояние для UI (`state()` → JSON/кадр) и принимает действия UI (`action(name, payload)` — «нажать», «повернуть на +3»);
   - текущие `set_level` / `wire` / `set_adc` становятся простейшими встроенными моделями («внешний уровень», «перемычка», «источник напряжения»), тесты переписываются на них.
   - Стенд должен работать и на плате (dry-run режим), не только на Mac.

3. **Захват ресурсов шире пинов.** `ResourceManager` должен уметь `i2c-1@0x3C`, `spi1.cs0`, `uart:ttyS3` (+ автоматически пины этих интерфейсов как `system`), а не только GPIO-линии.

4. **Реестр нод с источниками.** Типы нод грузятся из нескольких источников (встроенные, пользовательские блоки, **установленные модули**) с неймспейсами (`builtin.*`, `user.*`, `mod.<module>.*`) — заложить при создании реестра в фазе 1.

Pillow 10.3.0 (freetype есть), spidev, smbus2, pyserial, gpiod 2.1.3 — установлены; numpy — нет; glibc 2.39 (подходят aarch64-колёса `manylinux_2_28`).
