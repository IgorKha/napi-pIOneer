# 005 — Многофайловые проекты: скрипты, блоки и библиотеки как папки с кодом

- **Статус:** принято
- **Задевает спеку:** 3.6 (Python-блоки), 4 (UI: файловое дерево), 5 (хранилище, worker), 9 (деплой/CLI); идеи [001](001-modules-and-simulation.md) (модули/библиотеки), [004](004-sdk-docs.md) (подсказки/трейсбеки)
- **Когда вливать:** изоляция импортов — **сейчас** (это баг); «папка с кодом» + дерево файлов (А) — следующим шагом; CLI (Б) — сразу после; git-репо на плате (В) и зависимости проекта — потом.

## Идея

Скрипт может быть сложным проектом: несколько Python-файлов, подпапки, свои модули, ассеты (шрифты для дисплеев, картинки, конфиги, CSV). То же — для Python-блоков графа и общих библиотек.

## Найденный баг (исправить сейчас)

Сейчас скрипт = `data/scripts/<id>.py`, worker делает `runpy.run_path` с `cwd` = общей папкой `data/scripts/` → `sys.path[0]` общий для всех скриптов: `import <имя>` может подхватить **чужой скрипт** (или его `.json`-соседа по имени). Нужна изоляция: у каждого запуска свой корень в `sys.path`, `cwd` — корень своего проекта.

## Решения

1. **Единый движок «папка с кодом» (CodeTree)** для трёх сущностей — скрипты, Python-блоки, библиотеки (и позже модули 001). Одно файловое API, один файловый менеджер в UI, одни правила.

2. **Раскладка скрипта-проекта:**
   ```
   data/scripts/<id>/
     pioneer.json        # {name, entry: "main.py", autostart, restart_on_save, created, updated}
     main.py             # точка входа (entry настраивается)
     drivers/display.py  # свои модули, подпапки (обычные или namespace-пакеты)
     assets/font.ttf     # любые файлы
   ```
   Python-блок — та же раскладка (`data/blocks/<slug>/`, entry `block.py` с `@node`-классами, рядом — свои модули). Существующие однофайловые скрипты и блоки **мигрируют автоматически** (`<id>.py` → `<id>/main.py`, `<slug>.py` → `<slug>/block.py`).

3. **Импорты:** `sys.path` = [корень проекта, общие библиотеки, SDK]; `cwd` = корень проекта. Работают `from drivers.display import Oled`, относительные импорты, `Path(__file__).parent / "assets/font.ttf"`. Чужие проекты не видны.

4. **Общие библиотеки = модуль без нод и симуляции** (простейший случай модуля из 001): `data/lib/<name>/` (та же CodeTree-раскладка, `pioneer.json` с `kind: "lib"`). Видны всем скриптам и блокам, импорт по имени папки. Конфликт имени библиотеки с модулем проекта — проект побеждает, предупреждение в лог.

5. **Запуск:** «Запустить» = `entry`; «Запустить этот файл» — отдельный запуск выбранного файла (служебные скрипты: калибровка, прошивка EEPROM датчика) со своими захватами ресурсов, в логе — отдельной вкладкой. Опция проекта «перезапускать при сохранении».

6. **Трейсбеки и ошибки** показывают пути относительно корня проекта (`drivers/display.py:42`) и кликабельны → файл на строке в редакторе.

7. **Редактирование — ступени:**
   - **А (сейчас):** в браузере — дерево файлов (создать/переименовать/переместить drag-n-drop/удалить файлы и папки), вкладки, автосохранение, загрузка файлов (в т.ч. бинарных) и скачивание; импорт/экспорт проекта zip.
   - **Б (сразу после):** CLI на Mac `pioneer push | pull | watch <папка> [--project <id>]` — правишь в VS Code, сохранил → файлы уехали на плату (дифф по хешам, удаления тоже), опционально перезапуск. Аутентификация — API-ключ сервиса. Для коллег — тот же CLI (pip-пакет / один файл).
   - **В (потом):** проект как git-репо на плате (`git` есть): clone/pull из своего репозитория, тот же механизм, что источники модулей в 001.

8. **Подсказки в редакторе:** SDK — из `sdk-reference.json` (идея 004); символы своих файлов — пока по словам/открытым моделям Monaco. Полноценный кросс-файловый анализ (переход к определению, автокомплит своих классов) — **позже**, варианты: `jedi` (чисто питоновский, на бэкенде платы) или ограничиться VS Code через CLI (Б). Решить, когда станет больно.

9. **Зависимости проекта (`requirements.txt`) — потом** (механика общая с модулями 001: чисто-питоновские + aarch64-колёса, общий кеш колёс + per-project site-каталог).

10. **Ограничения и безопасность файлового API:** нормализация путей и запрет выхода за корень (`..`, симлинки), запрет служебных имён (`pioneer.json` правится только через API метаданных), лимиты (файл — 5 МБ, проект — 50 МБ, настраиваемо), бинарные файлы — только upload/download (в редакторе — превью для картинок), текстовые — UTF-8.

## Критерий готовности (А + Б)

Проект «Термостат»: `main.py` + `drivers/sht30.py` + `ui/oled.py` + `assets/font.ttf`; правка в VS Code → `pioneer watch` → перезапуск на плате → ошибка в `ui/oled.py:17` кликабельна в логе UI; соседний проект с файлом `drivers/sht30.py` не конфликтует; общий `data/lib/filters` импортируется обоими.

## Открытые вопросы

1. Формат CLI-синхронизации: свой протокол поверх REST (список хешей → загрузка изменений) или rsync по SSH (быстро, но нужен SSH-доступ коллегам).
2. Конфликты правок браузер ↔ CLI одновременно: last-write-wins с предупреждением или блокировка проекта «редактируется через CLI».
3. Python-блок из нескольких файлов: схема нод извлекается из `block.py` — достаточно ли, или разрешить `@node` в любом файле пакета.
