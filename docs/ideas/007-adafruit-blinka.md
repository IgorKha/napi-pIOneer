# 007 — Драйверы Adafruit (CircuitPython) на Napi-C: прослойка, раздел управления, поддержка в редакторе

- **Статус:** принято
- **Задевает спеку:** 3.6 (Python-блоки), 4 (UI: новый раздел, редактор кода), 5 (worker, HW); идеи [001](001-modules-and-simulation.md) п.5 (прослойки — принято, не реализовано), [005](005-multifile-projects.md) (зависимости, jedi), [006](006-simulation-per-run.md) (симуляция)
- **Когда вливать:** после хвостов ревью (#24–27); прослойка — до идеи 006, чтобы стенд сразу проверялся на настоящих драйверах.

## Идея

Тысячи готовых драйверов Adafruit (`adafruit-circuitpython-*`: BME280, SHT4x, SSD1306, PCA9685, NeoKey, …) должны работать на Napi-C **без правок** — в скриптах и Python-блоках, на железе и на стенде. Плюс удобный раздел для поиска/установки/обновления драйверов и помощь в редакторе: «подключить датчик» за пару кликов.

## Часть 1. Прослойка (Blinka-совместимое API поверх HW)

Свои модули `board`, `busio`, `digitalio`, `analogio`, `pwmio`, `microcontroller` (пакет `pioneer.compat.circuitpython`), подкладываемые в `sys.path` worker'а скрипта и blockhost'а. Всё идёт через общий HW → захваты ресурсов, безопасные состояния, понятные ошибки занятости и симуляция (006, включая гибрид) работают автоматически.

| Модуль | Объём |
|---|---|
| `board` | пины Napi-C: `board.J9_7`, `board.GPIO2_A4` (оба имени), `board.SCL`/`SDA` (= I2C1), `board.I2C()`, `board.SPI()`, `board.UART()` — синглтоны на включённые по умолчанию интерфейсы; `board.board_id = "napi_c"` |
| `busio` | `I2C(scl, sda, frequency)` → интерфейс по паре пинов из `boards/napi-c.yaml` (ошибка с подсказкой оверлея, если не включён); `try_lock/unlock`, `scan`, `writeto`, `readfrom_into`, `writeto_then_readfrom`; `SPI` (`configure`, `write`, `readinto`, `write_readinto`); `UART` (`read`, `readline`, `write`, `in_waiting`, `baudrate`) |
| `digitalio` | `DigitalInOut`, `Direction`, `Pull` (Pull — предупреждение: софтом не меняется, см. скилл/вендор-доки; учитывать подтяжки из идеи «подтяжки через DT»), `DriveMode` |
| `analogio` | `AnalogIn` (`value` 0…65535, `reference_voltage = 1.8`) |
| `pwmio` | `PWMOut` (`duty_cycle` 0…65535, `frequency`): аппаратный PWM, если пин — PWM2/PWM3 и интерфейс включён, иначе soft-PWM (≤ 500 Гц, предупреждение для серв) |
| `microcontroller` | `Pin`, `microcontroller.pin.*`, `cpu.temperature` → `NotImplementedError` с понятным текстом |

Критерий объёма: работает `adafruit_bus_device` (I2CDevice/SPIDevice) — на нём сидит почти каждый драйвер.

### Ловушка с зависимостями (обязательно)

Пакеты `adafruit-circuitpython-*` в `install_requires` тянут `Adafruit-Blinka` и `adafruit-platformdetect`. Настоящая Blinka не знает Napi-C (упадёт или перекроет наш `board`). Решение:

- поставляем **пакет-заглушку `Adafruit-Blinka`** (dist-info с подходящей версией, внутри — пусто/ре-экспорт нашей прослойки) и `adafruit-platformdetect`-заглушку с `board_id = napi_c`, установленные в общий site драйверов **до** резолва;
- установка драйвера = `pip install --only-binary=:all: --target <site>` с `--constraint`, фиксирующим заглушки (pip видит зависимость удовлетворённой); проверка после установки: в site нет настоящих `board.py`/`busio.py`/`digitalio.py` (иначе откат);
- остальные зависимости драйверов (`adafruit-circuitpython-busdevice`, `-register`, `typing-extensions`, …) — чисто питоновские, ставятся как обычно.

## Часть 2. Раздел «Устройства → Adafruit» (управление драйверами)

Сейчас уже есть «Модули» (свои пакеты, 001) и «Ядерные драйверы». Чтобы не плодить разделы — **один раздел «Устройства»** с вкладками: **Модули** · **Adafruit (CircuitPython)** · **Ядерные драйверы**.

Вкладка Adafruit:
- **Каталог/поиск**: по имени чипа или модуля («bme280», «oled», «servo») среди `adafruit-circuitpython-*` (индекс PyPI JSON / bundle-manifest Adafruit, кэш на плате; без интернета — только установленные). Карточка: чип, интерфейс (I2C/SPI/UART/GPIO), адреса по умолчанию, ссылка на доки/README, пример.
- **Статус совместимости**: «проверено на Napi-C» / «на стенде» / «не проверено» (бейдж ставится автотестом или вручную после успешного запуска).
- **Установка/обновление/удаление** одного драйвера со всеми зависимостями (кнопка, прогресс, лог pip), версии фиксируются; **общий site драйверов** `data/drivers/adafruit/` — один на все проекты (экономия места); проект/блок хранит в своём lock-файле, какие драйверы и версии использует → при обновлении драйвера предупреждение «используется в проектах X, Y» и проверка на стенде.
- **«Где используется»**: список скриптов/блоков/проектов, импортирующих драйвер.
- **Примеры**: пример из пакета (`examples/`) открывается как новый скрипт одним кликом, с подставленными пинами/интерфейсом Napi-C.
- **Связь с модулями (001)**: драйвер Adafruit + сгенерированная нода + модель стенда можно сохранить как модуль (п. 3.3 ниже).

## Часть 3. Поддержка в редакторе скриптов и блоков

1. **Мастер «Подключить устройство»** (кнопка в редакторе / команда `⌘K` → «Подключить…»): выбрать драйвер (из установленных или каталога, с установкой) → интерфейс и адрес/пины (только свободные и включённые, с подсказками подключения: питание, подтяжки, 3.3 В) → вставляет в текущий файл готовый код:
   ```python
   import board
   from adafruit_bme280 import basic as adafruit_bme280
   i2c = board.I2C()  # I2C1: J9-3 SDA, J9-5 SCL
   bme280 = adafruit_bme280.Adafruit_BME280_I2C(i2c, address=0x76)
   ```
   и добавляет драйвер в lock проекта.
2. **Автокомплит и подсказки**: `board.` — пины и интерфейсы Napi-C из `boards/napi-c.yaml` с описанием (J-номер, GPIO-имя, занятость); API драйверов — через jedi (language worker видит общий site драйверов и заглушки); hover — докстринги драйвера + ссылка на доки.
3. **Диагностика в редакторе**: неизвестный пин/интерфейс, пин занят другим проектом/ядром, интерфейс выключен (с кнопкой «как включить»), импорт неустановленного `adafruit_*` (quick-fix «Установить драйвер»).
4. **Блоки из драйвера**: в редакторе блоков — «Создать блок из драйвера»: генератор шаблона Python-блока (выходы по свойствам драйвера — `temperature`, `humidity`, `pressure`; входы для актуаторов — `angle`, `duty`; параметры — интерфейс/адрес/период опроса). Дальше блок правится как обычный; можно сохранить как модуль (001) с README и моделью стенда.
5. **Стенд**: для популярных чипов (BME280, SHT4x, SSD1306, PCA9685) — протокольные модели (001 п.6), чтобы драйвер Adafruit без правок работал в симуляции; для остальных — «нет модели», запуск только на железе или в гибриде с этим ресурсом на железе.

## Критерий готовности

1. В новом скрипте мастер «Подключить устройство» → BME280 (I2C1, 0x76) ставит `adafruit-circuitpython-bme280` из PyPI без правок, вставляет код; скрипт читает температуру с **настоящего** датчика.
2. Тот же скрипт в режиме симуляции (006) читает значение из модели стенда (слайдер температуры).
3. `adafruit-circuitpython-ssd1306` + `adafruit-circuitpython-framebuf` рисуют текст на OLED (I2C) на плате и на стенде.
4. «Блок из драйвера» для BME280 → нода с выходами T/H/P работает в графе.
5. В site драйверов нет настоящей Blinka; `board`/`busio` — наши; удаление драйвера, используемого проектом, требует подтверждения.

## Решено (2026-10-11)

1. **Каталог:** поиск по Adafruit CircuitPython Bundle manifest (описания, чипы, категории; кэш на плате), установка — из PyPI (`adafruit-circuitpython-*`, колёса). Без интернета — только установленные.
2. **Общий site драйверов** `data/drivers/adafruit/` на все проекты, одна версия каждого драйвера на плату. Проекты/блоки фиксируют используемые версии в своём lock; обновление/удаление драйвера, который где-то используется, — с предупреждением и списком проектов.
3. **`Pull.UP/DOWN`:** программная подтяжка на vendor-ядре не работает, поэтому `digitalio` при запросе Pull проверяет текущую подтяжку пина (pinconf / конфиг `pulls.py`): совпадает — ок; не совпадает — предупреждение в лог и **предложение применить DT-подтяжку** через существующий механизм `pulls.py` (план + подтверждение + перезагрузка). В редакторе — та же диагностика с quick-fix «Настроить подтяжку J10-2 → pull-up (нужна перезагрузка)». Скрипт при этом не падает. На стенде Pull применяется сразу (модель пина).
