## Принцип: один источник правды

Справочник API **генерируется из кода**, руководства и рецепты — markdown с **исполняемыми** примерами.

```
pioneer.sdk (__all__, сигнатуры, type hints, докстринги)
boards/napi-c.yaml (пины, caps, интерфейсы)          ──►  sdk-reference.json  ──►  UI «Справка»
docs/sdk/*.md (руководства, рецепты, ошибки)                                  ──►  Monaco: completion / hover / signature help
                                                                              ──►  знания AI-помощника
                                                                              ──►  статический сайт (GitHub Pages и т.п.)
```

- **Генератор** (`tools/gen_sdk_reference.py`, запускается в `make build` и в CI): проходит `pioneer.sdk.__all__`, собирает сигнатуры, типы, дефолты, докстринги (формат: краткое описание + `Args:` / `Returns:` / `Raises:` / `Example:` / `Hardware:`), подтягивает из `boards/*.yaml` **списки пинов/интерфейсов, поддерживающих каждый класс** (не писать руками).
- **Тест покрытия документации:** у каждого публичного символа и параметра есть описание, иначе CI падает.
- **Исполняемые примеры:** каждый блок кода из `docs/sdk/*.md` и `Example:` в докстрингах помечен и прогоняется в pytest на `BenchHAL` (с моделями: кнопка, LED, перемычка, источник напряжения). Сломался пример — падает тест.
- **Ручной completion-провайдер в `CodeEditor.tsx` заменяется** на данные из `sdk-reference.json` (completion, hover с докстрингом и ссылкой «подробнее», signature help, диагностика неизвестных пинов/интерфейсов по board-yaml).
- Справка версионирована вместе с сервисом и **работает офлайн** (бандлится во фронт/отдаётся бэкендом).
- Язык — русский (UI русский), идентификаторы — английские. Для коллег — позже можно EN-версию тем же генератором.

## Структура раздела «Справка»

1. **Начало:** установка/доступ, первый скрипт (кнопка → LED), как устроен цикл событий (обработчики, `every`/`after`, автозапуск цикла), остановка скрипта (выходы → безопасное состояние, LED → системный триггер), ошибки в обработчиках не роняют скрипт.
2. **Справочник API** (генерируется): страница на символ — сигнатура, параметры с единицами и диапазонами, ограничения (PWM ≤ 500 Гц, ADC 0…1.8 В/10 бит), **поддерживающие пины/интерфейсы платы**, железные предупреждения, примеры.
3. **Рецепты:** мигалка; кнопка с debounce и `active_low`; долгое нажатие; ADC со скользящим средним и делителем; плавный PWM; I2C — чтение chip-ID (BME280 `0xD0`); UART — отправка/приём строк; Modbus RTU поверх `UART` (когда появится); позже — дисплей, энкодер, серва (модули 001), удалённые команды (003).
4. **Железо** (из скилла `napi-c` и `vendor-docs.md`): распиновка J9/J10 с картинкой платы из UI, 3.3 В логика и ток пина, реле только модулем с драйвером, делитель для ADC, подтяжки (софтом не меняются), I2C-подтяжки и адреса, RS-485, питание серв, «как не сжечь плату».
5. **Каталог ошибок:** текст `PioneerError` → причина → что делать (пин занят другим проектом/драйвером ядра/процессом, интерфейс не включён оверлеем, NACK на I2C = `ENXIO`, …). Ссылка из строки ошибки в логе скрипта.
6. **Позже, по мере появления:** ноды графа (из `doc` схем нод, спека 3.6), SDK Python-блоков, модули (001), удалённые команды (003), AI-помощник.

## Контекстная справка

- Hover / F1 на символе в редакторе → докстринг + «подробнее».
- Инспектор пина → «Как использовать в скрипте»: готовые сниппеты с этим пином (`Output("J9-7")`, `Input("J9-7", debounce_ms=30)`, `Adc("J9-26")` — только поддерживаемые пином режимы).
- Инспектор интерфейса (UART/I2C/SPI) → сниппет `UART("uart3")` и т.п.
- Строка ошибки в логе → статья каталога ошибок.
- Поиск по справке (Ctrl+K) по символам, рецептам и ошибкам.
- У каждого примера в справке: «Открыть в редакторе», «Запустить на стенде».

## Найдено при ревью SDK (2026-10-11)

1. **Адресация непоследовательна:** GPIO — по пинам (`"J9-7"`), шины — по номеру/пути (`I2C(bus=1, …)`, `UART("/dev/ttyS3")`). **Решено: унифицировать сейчас** — шины по id интерфейса из `boards/napi-c.yaml` (детали в handoff).
2. **`sleep()` в обработчике блокирует весь цикл** (другие кнопки/таймеры замирают). В справке — явное предупреждение и рецепт через `after()`; в рантайме — предупреждение в лог, если обработчик выполнялся дольше ~100 мс.
3. **`Event` сейчас = только фронт GPIO.** С идеей 003 события получат данные/контекст — описывать `Event` в справке так, чтобы расширение не стало ломающим (поля `pin`/`rising` остаются, добавляются `source`, `payload`).
