# Драйверы ядра через Pioneer

Пользовательская инструкция: [SDK: драйверы](sdk/drivers.md).

Универсальный `KernelPackages` принимает доверенные ARM64 `.ko` и ZIP с manifest,
модулями в порядке зависимостей и необязательным DTBO. Новый пакет не требует правок
core. `modinfo` определяет настоящие имена/зависимости; параметры передаются списком
аргументов без shell. Проверяются ELF, полное vermagic, SHA-256 перед каждой загрузкой,
ограничения архива, пересечения имён пакетов, загрузка предыдущей версии. Файлы приватны,
разделены по kernel release. Автозагрузка opt-in, выгрузка без force; частичная загрузка
откатывает только модули текущей попытки. Неудачная автозагрузка не останавливает core.

API `/drivers/packages`: GET каталог, POST raw `.ko`/ZIP с `confirmed=true`;
`/{id}/load|unload?confirmed=true`, `/{id}/autoload` (enabled, confirmed),
`/{id}/plan|apply` (enabled, hash, confirmed). DTBO применяется как
`pioneer-driver-{id}` с общим boot-lock, проверкой цепочки, свежего хэша и GPIO,
бэкапом и откатом записи. Декларации pins/device_nodes — контракт автора доверенного
пакета; структурная проверка DTBO не доказывает его безопасность для произвольной платы.

Готовый профиль — DHT22/AM2302 через `dht11`, Linux IIO и генерируемый оверлей
`pioneer-dht22`. Его SDK/нода дополняют универсальную установку. API не принимает
команды оболочки или произвольные пути sysfs/boot. Загрузка и применение требуют
явного подтверждения, авторизованной сессии и CSRF-заголовка. ELF/vermagic не заменяют
доверие к происхождению модуля. Готовый профиль поддерживает один DHT22;
другие системные драйверы устанавливаются универсальными пакетами. SDK-обёртки
и графические ноды для их специфичных интерфейсов добавляются отдельно.

API: GET `/drivers`; POST `/drivers/dht22/module?confirmed=true` (сырой .ko, ≤1 МиБ),
`/load?confirmed=true`, `/plan` и `/apply` (pin, enabled, hash, confirmed), `/read`.
`/board/reboot` остаётся отдельным подтверждённым действием.

Применение сохраняет обычные boot-оверлеи и остальные `user_overlays`, проверяет
актуальный хэш и владельцев пина, использует общий lock с настройкой интерфейсов.
Компиляция/проверка DTB выполняется до GPIO-lock, чтобы не блокировать таймеры выходов.
Данные и .ko приватны, kernel release определяет каталог .ko. На следующем старте
core загружает установленный модуль только для явно включённого подключения.
SDK и нода читают через общий IIO-кэш; протокол не исполняется в userspace.

готовым профилем; повторно добавлять второй оверлей для того же датчика не нужно.

На реальной плате проверены универсальные upload/load/unload, загрузка через
профиль, затем stop сервиса → rmmod → start и автозагрузка с polling=1.

Пример скрипта «DHT22: температура и влажность» оставлен остановленным,
автозагрузка пакета включена. 256 тестов прошли, frontend собран и выложен.
Универсальное применение DTBO проверено тестами с откатом записи; на плате
применён и проверен после перезагрузки оверлей готового профиля DHT22.
