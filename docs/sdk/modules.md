# Модули периферии

Настройки → Модули устанавливают ZIP или HTTPS git-репозиторий (тег/ветка, фактический commit сохраняется). Установка требует доверия к Python-коду. Код исполняется в отдельных worker-процессах, не в core; это изоляция отказов, не песочница для враждебного кода.

Скачайте учебный модуль прямо со страницы: он содержит реальный Python-драйвер учебного I2C-регистра, ноду, протокольный симулятор и JS-виджет. Это пример протокола, не драйвер подключённого физического датчика.

## Пакет

Обязательны module.yaml, README.md и Python-файл с @node из pioneer.block. Драйверы и ассеты — обычные файлы рядом. Пример манифеста:

```yaml
id: register_demo
version: 1
title: Регистр I2C
entry: block.py
connection: I2C1, адрес 0x48, питание согласно README
model:
  entry: simulation.py
  params:
    bus: {type: int, default: 1}
    addr: {type: int, default: 72}
    value: {type: int, default: 1234}
  actions: [set]
widget: widget.js
```

Версия — целое 1…9999. Тип ноды получается `module.register_demo.read@1`. Версии установлены рядом; изменённый код требует новой версии. Удаление запрещено, пока модуль используется проектом или симулятором.

## Зависимости

requirements.txt содержит до 32 строк `name==version`, можно extras. URL, editable, pip-опции и сборка исходников запрещены. Ставятся совместимые колёса в отдельный каталог data/dependencies, системный Python не изменяется. Для скрипта/своего блока есть кнопка «Установить зависимости» в дереве файлов. После установки набор неизменяемый: для изменения используйте новую версию модуля или отдельный проект. Для загрузки нужен интернет и pip в Python сервиса.

## Драйвер и симулятор

Нода в setup получает `self.hw.i2c("i2c1", 0x48)`. Устройство поддерживает write/read/write_read/read_reg/write_reg, GPIO — input/output/read/write. Операции проходят через HAL и общие захваты; один код работает на Linux и Bench.

simulation.py объявляет `Simulation(config)`. Методы i2c_write(bus, addr, hex), i2c_read(bus, addr, n) → hex и spi_xfer(bus, cs, hex) → hex реализуют протокол. state() → JSON и action(name, payload) управляют виджетом. GPIO-модель может реализовать on_gpio/on_pwm и объявить наблюдаемый pin в конфигурации. Модель исполняется отдельным процессом; зависание ответа прекращает этот симулятор, не core. Стенд работает только при HAL=bench.

widget.js экспортирует `mount(el, props, emit)`, где props содержит state/config. Виджет загружается в iframe без доступа к cookies, DOM родителя и сети. `emit(name, payload)` вызывает только действия, объявленные манифестом. При изменении состояния mount вызывается заново; храните долговременное состояние в модели. Без widget.js показывается JSON.

## Перенос

«ZIP с блоками» в редакторе графа переносит граф, используемые Python-блоки и модули, а также общие библиотеки. requirements включены; пакеты с ними устанавливаются при подтверждённом импорте. Системные бинарники и секреты не переносятся. Импорт создаёт остановленную копию и откатывает собственные новые записи при ошибке. Разный код с тем же типом/версией или именем библиотеки блокирует импорт.

Полная эмуляция CircuitPython/Blinka, каталог PyPI-модулей и автоматические сценарии стенда остаются расширениями концепции; установка произвольного совместимого Python-пакета через requirements уже поддержана.
