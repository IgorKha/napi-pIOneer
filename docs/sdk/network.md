# Сеть и удалённое управление

## MQTT

В «Настройки → MQTT» задайте адрес брокера, порт, пользователя и секрет пароля. Используйте отдельный topic base, чтобы тесты и реальные устройства не мешали друг другу. Состояние подключения видно в диагностике системы.

Нода «Команда» принимает структурированные команды по MQTT и HTTP, «Публикация» публикует события и значения, «Состояние» отдаёт retained-состояние. Нода «Поле JSON» позволяет разобрать payload и извлечь нужное поле. Неверный JSON обрабатывайте как ошибку, а не как новое значение датчика.

## Команды и состояние

Настройте базовый topic и имя команды. «Команда» объявляет схему аргументов и проверяет входящий payload. «Ответ» возвращает результат; одинаковый id предотвращает повторное исполнение в пределах текущего процесса. Схемы и состояния доступны через describe. Watch и лог помогают проверить доставку до подключения нагрузки.

Для домашнего тестового брокера уже подготовлены примеры в docs/home-mqtt.md. Пароли находятся в секретах системы; их нет в этом руководстве.

## HTTP и изображения

HTTP-запросы выполняются вне потока движка. Проверяйте статус и ошибку до передачи результата дальше. Media-ноды могут получать изображение по URL и передавать его в обработку, включая AI.

Физическая ESP32-CAM отложена отдельной задачей по договорённости. Для проверки цепочки используется генератор тестовой картинки tools/media-test-server.py. Такая проверка не подтверждает питание, устойчивость Wi-Fi или совместимость настоящей камеры.

## Отказ сети

Не считайте последнее значение свежим бесконечно. Используйте таймер, valid/error датчика, статус соединения и безопасное состояние выхода. При остановке проекта сетевые задачи завершаются, ресурсы освобождаются.
