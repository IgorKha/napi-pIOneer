# Драйверы ядра: универсальные пакеты и DHT22 / AM2302

## Универсальная установка через админку

В **Настройки → Драйверы → Пакеты драйверов** можно загрузить любой доверенный
ARM64 `.ko`, совместимый с текущим ядром, либо ZIP с несколькими модулями и
необязательным boot-оверлеем. Для нового пакета не нужны изменения Pioneer или
пересборка ядра платы. Сборка самого `.ko` под нужное ядро остаётся обязательной;
модули для другой версии/ABI не подходят. Проверка ELF/vermagic не подтверждает
происхождение кода, который будет работать с правами ядра.

Одиночный `.ko` получает имя/описание/зависимости из `modinfo`. ZIP содержит только
обычные файлы в корне и `manifest.json`, например:

```json
{
  "id": "dht22",
  "title": "DHT22 / AM2302",
  "modules": ["dht11.ko"],
  "overlay": "sensor.dtbo",
  "pins": ["J10-16"],
  "device_nodes": ["/pioneer-dht22"],
  "parameters": {"dht11": ["polling=1"]}
}
```

- `modules` — имена файлов `.ko` в порядке загрузки зависимостей. Зависимости,
  уже имеющиеся в системе, загружаются через `modprobe`; приватные зависимости
  включите в пакет раньше потребителя.
- `overlay` — необязательный готовый `.dtbo` именно для этой платы и подключения.
  GPIO в DTBO фиксирован; для другого пина автор пакета должен собрать другой DTBO.
- `pins` — все эксклюзивные GPIO, которые занимает оверлей; общие SDA/SCL сюда не
  входят. `device_nodes` — полные пути его устройств в DT для проверки уже занятого
  пина. Корректность этих деклараций лежит на авторе доверенного пакета.
- `parameters` — необязательный объект `имя_модуля: ["параметр=значение"]`.
  Команды оболочки в параметрах не выполняются.

Установка не загружает код и не меняет boot. Затем явно нажмите **Загрузить** и
при необходимости включите **Автозагрузку**. Если устройство уже описано в DT
либо обнаруживается автоматически (например USB), отдельный оверлей не нужен.
Для нового DT-устройства откройте **Предпросмотр подключения**: выводится
декомпилированный DTBO, diff uEnv, конфликты GPIO; вся следующая цепочка оверлеев
проверяется на реальном DTB. Применение сохраняет бэкап, перезагрузка отдельная.

ZIP ограничен 16 МиБ, распакованные файлы — 32 МиБ, DTBO — 256 КиБ. Файлы пакета
хранятся приватно отдельно для версии ядра. Обновление загруженных модулей запрещено;
сначала остановите потребителей, отключите автозагрузку, выгрузите пакет. Принудительной
выгрузки нет: ядро отклоняет выгрузку используемого модуля. Если сборка/загрузка
пакета не удалась, Pioneer продолжает работу; ошибка отражается в журнале.

Универсальная установка предоставляет системный драйвер и его `/dev`/sysfs-интерфейсы.
Готовые SDK-обёртки и ноды — отдельные удобные профили, первый из них DHT22.

## Готовый профиль DHT22

На этой Napi-C GPIO IRQ пропускает фронты стандартного `dht11`. Подготовленный
пакет использует опциональный параметр `polling=1`: фронты фиксируются коротким
опросом внутри ядра, без userspace bit-bang. Критическая секция на одном CPU
ограничена 8 мс, на время кадра локальные IRQ отключены; это добавляет задержку
прерываний этого CPU. Режим запрещён для GPIO-контроллера, который может спать.
CRC/декодирование остаются штатными, кэш — 2 с. Такой режим не предназначен для
задач с жёсткими ограничениями задержки IRQ. Обычно захват занимает около 4 мс.

Он задаётся в manifest пакета, без изменений универсального загрузчика:

```json
"parameters": {"dht11": ["polling=1"]}
```

Скрипт сборки применяет `tools/kernel-drivers/dht11-bounded-polling.patch`
к точному vendor-исходнику. Этот патч нужен конкретному модулю/контроллеру,
а не каждому новому драйверу. Основное ядро платы не меняется. Если установлен
универсальный пакет с `dht11`, профиль использует его параметры и автозагрузку;
включите **Автозагрузку** в карточке пакета.

Драйвер Linux `dht11` поддерживает DHT11 и DHT22. Он ловит фронты DATA в ядре и
выдаёт измерения через IIO; Python не исполняет чувствительный к задержкам протокол.
Красная плата модуля не определяет порядок контактов: смотрите DAT/VCC/GND на модуле.

## Подключение на этой плате

- DAT → J10-16 (GPIO3_B2, банк 3 / линия 10).
- VCC → J9-1 (+3V3).
- GND → J10-1.
- DATA подтянут к 3.3 В: резистор на модуле или внешний 4.7–10 кОм.

Не подавайте 5 В на DATA. Оверлей включает GPIO и подтяжку вверх; внешний резистор
остаётся необходимым, если на модуле его нет или линия длинная.

## Включение через панель

Откройте **Настройки → Драйверы**. Панель показывает версию ядра, наличие модуля,
его загрузку и наличие датчика в IIO.

1. Если модуль отсутствует, загрузите подготовленный **dht22.zip** в разделе
   **Пакеты драйверов**: он содержит dht11.ko и параметр polling=1 для этой платы.
   Проверяются ELF ARM64 и полное vermagic с эталонным модулем системы.
   Эти проверки выявляют несовместимость, но не подтверждают происхождение файла.
2. Загрузите пакет в ядро и включите его автозагрузку. Уже загруженный модуль
   повторно не вставляется. Кнопка готового профиля тоже использует этот пакет.
3. Выберите DATA-пин и нажмите **Предпросмотр подключения**.
   Панель покажет DTS и diff uEnv, проверит занятость GPIO, скомпилирует оверлей
   и проверит всю цепочку следующей загрузки через fdtoverlay на DTB этой платы.
4. Явно подтвердите применение. Создаётся отдельный бэкап uEnv, конфигурации датчика
   и предыдущего оверлея. Перезагрузка выполняется отдельной кнопкой.
5. После перезагрузки нажмите **Прочитать датчик**. Ядро держит DATA-пин;
   использовать его как обычный GPIO в скриптах/графах нельзя.

На текущей NapiLinux 0.3.1 ядро **6.6.89-g56f90cb4cd7d**, `CONFIG_IIO=y`,
`CONFIG_DHT11` выключен. Заголовков ядра на плате нет. `CONFIG_OF_OVERLAY` тоже
выключен, поэтому добавление устройства требует boot-оверлея и перезагрузки.
Прошивку или Image для установки отдельного совместимого модуля заменять не нужно.

## Скрипт

```python
from pioneer.sdk import DHT22, every, log

sensor = DHT22()

@every(5)
def measure():
    sample = sensor.read()
    if sample["ok"]:
        log(sample["temperature"], "°C", sample["humidity"], "% RH")
    else:
        log(sample["error"])
```

Core сериализует чтение и кеширует результат/ошибку на 2 с для всех потребителей.
Не подключённый драйвер вызывает `PioneerError`; ошибка ответа датчика даёт `ok=False`.

## Граф

Нода **DHT22 / AM2302 (ядро)** выдаёт температуру, влажность, корректность измерения,
ошибку и событие «Измерено». Чтение выполняется вне потока движка. При ошибке
числовые выходы остаются последними успешными значениями, а `valid=false`;
используйте этот сигнал, чтобы нагрузка не управлялась по устаревшему измерению.

## Сборка модуля

Нужна подготовленная сборка **точной vendor-ревизии и конфигурации ядра платы**,
ARM64 cross toolchain и `Module.symvers`. Одного `make modules_prepare` недостаточно
для проверенной таблицы экспортируемых символов. Исходный драйвер:
`drivers/iio/humidity/dht11.c` в vendor kernel, на этой плате commit `56f90cb4cd7d`.

В репозитории Pioneer есть `tools/kernel-drivers/build-dht11.sh`:

```sh
CROSS_COMPILE=aarch64-linux-gnu- tools/kernel-drivers/build-dht11.sh /path/kernel-source /path/kernel-build ./dht11-output
```

Для исходников из архива сохраните суффикс версии через `LOCALVERSION` при
подготовке ядра и сборке модуля; для этой платы это `-g56f90cb4cd7d`. Скрипт
проверяет, что версия модуля совпала с подготовленным `UTS_RELEASE`.

Он собирает только `dht11.ko` как внешний модуль, не меняет Image, DTB или конфигурацию
платы. Модуль хранится в приватном каталоге данных Pioneer, отдельно для каждой версии
ядра. После обновления прошивки требуется модуль для новой версии; несовместимый
модуль не загружается. Автозагрузка действует только для явно применённого подключения.

## Ошибки и восстановление

Нет IIO-устройства: проверьте наличие модуля, оверлей и факт перезагрузки.
Нет ответа/CRC: проверьте проводку, DATA-подтяжку, питание и журнал `dmesg`.
Неудачная запись конфигурации откатывается; бэкап остаётся в данных Pioneer.
Если ошибка загрузочного оверлея мешает старту, восстановите uEnv из указанного бэкапа
через UART-консоль или microSD. Отключение через админку удаляет только
`pioneer-dht22` из `user_overlays`; остальные оверлеи сохраняются, затем нужна перезагрузка.

Источник: [Linux Device Tree binding DHT11/DHT22](https://www.kernel.org/doc/Documentation/devicetree/bindings/iio/humidity/dht11.txt).
