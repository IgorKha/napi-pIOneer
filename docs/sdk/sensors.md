# Датчики I2C

SHT30/SHT31 и BH1750 доступны как ноды графа и классы SDK. Они работают через уже включённый I2C и не требуют своего модуля ядра или изменения загрузки платы.

## Подключение

| Сигнал | Napi-C, I2C1 |
| --- | --- |
| SDA | J9-3 |
| SCL | J9-5 |
| VCC | J9-1, 3.3 В |
| GND | J10-1 |

Подтяжки SDA/SCL должны идти к 3.3 В. Проверьте распиновку именно своего модуля. Не подключайте к этим линиям 5 В. Не запускайте одновременно несколько читателей одного адреса.

| Датчик | Адреса | Результат |
| --- | --- | --- |
| SHT30 / SHT31 (SHT3x-DIS) | 0x44 / 0x45, в UI 68 / 69 | Температура °C, влажность % RH |
| BH1750 | 0x23 / 0x5C, в UI 35 / 92 | Освещённость в люксах |

## В графе

Выберите ноду в категории «Датчики», задайте шину, адрес и интервал. Чтение происходит в отдельной задаче и не блокирует таймеры графа. valid=false означает, что последнее измерение не удалось; error содержит причину. Числовые выходы сохраняют последнее успешное значение. measured выдаёт событие только после успешного измерения.

У SHT3x проверяются обе контрольные суммы CRC. BH1750 использует одноразовое измерение с ожиданием 180 мс. Адрес захватывается проектом или скриптом; конфликтующий второй владелец не запускается.

## В скрипте

```python
from pioneer.sdk import SHT30, BH1750, every, log

climate = SHT30("i2c1", 0x44)
light = BH1750("i2c1", 0x23)

@every(5)
def sample():
    log(climate.read())
    log(light.read())
```

read() синхронный: BH1750 занимает примерно 180 мс, поэтому не используйте его внутри быстрого обработчика кнопки. Ошибки шины и CRC поднимаются как PioneerError. Частоту опроса выбирайте с учётом других обработчиков скрипта.

## Границы проверки

Протоколы, повреждённые ответы, владение адресами и восстановление после ошибки проверяются на стенде. Физические SHT30/BH1750 к текущей плате не подключены, чтение с настоящих датчиков ещё не подтверждено. DHT22 на J10-16 — отдельный драйвер ядра; см. [Драйверы](drivers.md).
