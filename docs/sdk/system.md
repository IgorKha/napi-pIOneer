# Диагностика и обслуживание

## Диагностика системы

«Настройки → Система» показывает память core, доступную RAM, место для данных, время работы, запущенные проекты и скрипты, захваты ресурсов, MQTT и загруженные драйверы. Кнопка обновления получает текущие значения. На локальном стенде Linux-показатели памяти могут быть недоступны.

Предупреждения появляются при превышении бюджета core 120 МиБ, остатке RAM меньше 64 МиБ или свободном месте меньше 64 МиБ. Это повод проверить активные процессы и данные, а не автоматически перезапускать плату.

## Отчёт для диагностики

«Скачать отчёт» сохраняет JSON с перечисленными показателями. Отчёт не содержит ключи, пароли, cookies, код, логи и переменные окружения. Перед передачей дополнительно проверьте, подходит ли вам раскрытие версии ядра и идентификаторов установленных драйверов.

## Сохранность данных

Код приложения и данные находятся в скрытом каталоге .pioneer на разделе Data. Экспорт проекта и ZIP скрипта — отдельные переносимые копии, а не полный бэкап всех настроек. Секреты храните отдельно от экспортов кода.

## Интерфейсы и драйверы

Пины включённых интерфейсов недоступны для ручного GPIO. Смена pinmux требует проверки конфликтов, резервной копии и перезагрузки. Загружаемые модули ядра должны совпадать с установленным ядром; подробности в [Драйверы](drivers.md).

## Если что-то не работает

Сначала проверьте [Ошибки](errors.md), статус проекта, занятые ресурсы и наличие интерфейса. Затем сохраните отчёт и нужный фрагмент логов. Не публикуйте secrets.json и auth.json.

## Аппаратный watchdog

Настройки → Система показывают доступность /dev/watchdog0 и политику восстановления. По умолчанию watchdog выключен; после рестарта включается вручную. Ядро должно разрешать отключение (nowayout=0) и поддерживать magic close. Открытие устройства уже включает таймер, поэтому диагностика его не открывает.

После явного подтверждения core запрашивает таймаут 30…180 с (ядро может округлить его), затем периодически проверяет event loop и движок графов и кормит watchdog. Падение/зависание core прекращает heartbeat и приводит к аппаратному reset. При штатной остановке записывается magic V и устройство закрывается. Ошибка отдельного пользовательского worker не вызывает reset всей платы. После рестарта нужно включить watchdog заново: автоматический перезапуск приложения выполняет systemd, автозапуск watchdog намеренно не включён.
