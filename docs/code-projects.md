# Многофайловые скрипты, блоки и библиотеки

Скрипты хранятся в `data/scripts/<id>/`, Python-блоки — в `data/blocks/<id>/`,
общие библиотеки — в `data/lib/<имя>/`. Метаданные — `pioneer.json` внутри папки.
Старые `.py` + `.json` автоматически переносятся при запуске сервиса. Миграция
сохраняет id, имя, автозапуск и даты; конфликт с уже существующей папкой останавливает
миграцию и сохраняет оригиналы.

В редакторах «Скрипты» и «Блоки» доступны дерево файлов, вкладки, создание файлов/папок,
переименование и перенос (в том числе перетаскиванием в папку), удаление, загрузка
бинарных файлов, превью PNG/JPEG/GIF/WebP и импорт/экспорт ZIP. ZIP сливается с папкой:
метаданные назначения и файлы, отсутствующие в архиве, сохраняются. Все пути и
структурные конфликты проверяются до записи; отдельные файлы записываются атомарно.
При ошибке диска во время записи архив может быть применён частично — экспортируйте
резервную копию перед большим импортом.

Автосохранение — после паузы 1.2 с; при ошибке выключается, правки остаются в редакторе.
Перед переключением проекта дождитесь «Сохранено» или нажмите ⌘S / Ctrl+S.
Правки браузера и CLI: последняя сохранённая версия побеждает; открытые вкладки не
перечитываются автоматически после правок CLI. Перезагрузите страницу перед переходом
из VS Code обратно в браузер.

У скрипта есть настраиваемый `entry` (изначально `main.py`) и опция «перезапуск при
сохранении». «Этот файл» запускает выбранный Python-файл вместо точки входа; сначала
останавливает текущий запуск этого скрипта, сохраняя те же захваты ресурсов и лог.
Одновременные отдельные служебные запуски внутри одного скрипта пока не поддерживаются.
Точка входа защищена от удаления/переноса: сначала назначьте другую.

Блоки извлекают схемы из `block.py`; вспомогательные файлы импортируются обычным Python.
Изменение любого файла блока повторно проверяет схему, запущенные графы подхватывают
код через «Применить». Встроенная Script-нода имеет отдельную папку кэша для каждого
хэша кода. Локальные импорты блоков из разных папок изолированы даже внутри одного
worker-процесса. Код доверенный, это изоляция импортов, а не security sandbox.

Общие библиотеки создаются внизу списка скриптов. Например `filters/__init__.py`
содержит `def smooth(...)`: `from filters import smooth` доступен скриптам и блокам.
При совпадении имён модуль проекта имеет приоритет. Импорт из соседнего скрипта/блока
через обычный `import` не доступен. Файлы библиотек с `pioneer.json` в импортах не участвуют.
Лимиты: файл 5 МБ, проект 50 МБ и 2000 файлов/папок. Симлинки, `..` и редактирование
`pioneer.json` через файловое API запрещены.

## CLI: VS Code → плата

CLI — один файл `tools/pioneer-cli/pioneer.py`, Python 3.10+, зависимостей нет.
Создайте скрипт/блок/библиотеку в UI, возьмите id из адреса страницы (для библиотеки — имя).
В «Настройки» создайте отдельный секрет `code_api_key`: он даёт доступ к исходникам
и запуску скриптов; ключ удалённых команд `remote_api_key` такого доступа не имеет.

```bash
export PIONEER_URL='https://192.168.1.161'
# Задайте PIONEER_CODE_KEY значением секрета code_api_key в своей оболочке.
python3 tools/pioneer-cli/pioneer.py pull ./thermostat --project <id>
python3 tools/pioneer-cli/pioneer.py push ./thermostat --project <id> --restart
python3 tools/pioneer-cli/pioneer.py watch ./thermostat --project <id> --restart
```

Для самоподписанного сертификата добавьте `--insecure` (только для своей доверенной платы).
`--kind blocks` или `--kind lib` выбирает блок/библиотеку. Синхронизация сравнивает SHA-256;
неизменённые файлы не загружаются повторно. `.git`, `.venv`, `__pycache__`, `node_modules`
не синхронизируются. Метаданные меняются отдельным API: для скрипта поддержаны имя,
entry, autostart, restart_on_save; id и служебные поля никогда не заменяются из папки.

Удаления передаются только с `--delete`; без него отсутствующие файлы у назначения
сохраняются. `pull` заменяет локальные файлы совпадающих имён: коммитьте правки перед
получением новой версии. `watch` проверяет каждые 2 с и повторяет при сетевом обрыве;
ошибка валидации останавливает CLI и выводит причину. Watch не стартует сервисы и
не устанавливает зависимости. `--restart` доступен только для скриптов.

Файловое API: `/pioneer/api/code/<scripts|blocks|lib>/<id>/tree|file|upload|download|mkdir|move|delete|export.zip|import.zip`.
Авторизация: обычная сессия с CSRF или заголовок `X-Pioneer-Key` со значением `code_api_key`.
Ни один ключ не кладётся в проект, ZIP или URL.

## Проверка

`backend/tests/test_codetree.py`: миграция, реальные workers с драйвером/ассетом/библиотекой,
изоляция двух блоков с одинаковыми импортами, проверка путей/симлинков/ZIP/лимитов,
API/CSRF/ключ, обновление схем после изменения helper, CLI push/pull/удаления.
Локальный UI smoke: вложенный файл → код в Monaco → сохранение → «Этот файл» → вывод 42.
2026-10-11 версия установлена на Napi-C `192.168.1.161`: мигрированы два скрипта и два
блока, исходники и метаданные совпадают с резервной копией; четыре прежних графа сохранены.
На реальном worker проверены локальный импорт, бинарный ассет, ZIP export/import и
CLI `pull` / `push --restart`. Тестовый скрипт `f29c8738` («CodeTree: проверка после
деплоя») оставлен без автозапуска. MQTT и автозапуск тестового графа проверены после
перезапуска сервиса: [домашний MQTT](home-mqtt.md). Перезагрузка ОС и физические GPIO
в этой проверке не использовались.
