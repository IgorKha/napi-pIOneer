# Тестовый стенд на реальной плате

Что физически подключено к Napi-C разработчика (`192.168.1.161`) для проверок на железе.
Виртуальный стенд (BenchHAL) — отдельно, см. spec 5.2.

> J9 на плате развёрнут на 180°: pin 1 (+3V3) — снизу справа, pin 2 (+5V) — снизу слева,
> pin 26 (ADC_IN0) — сверху слева. У J10 pin 1 (GND) — сверху слева. Подробно — `boards/napi-c.yaml`.
> Перекоммутацию делать при выключенной плате.

## Подключения

| Что | Пин модуля → плата | Сигнал | Примечание |
|---|---|---|---|
| **UART-петля** | перемычка **J10-13 ↔ J10-14** | ttyS3 TX ↔ RX (UART3 m0, включён по умолчанию) | Порт никто не держит (getty только на ttyS2) |
| **DHT22** (AM2302, модуль на красной плате) | DAT → **J10-16**, VCC → **J9-1** (+3V3), GND → **J10-1** | GPIO3_B2 (gpiochip3:10) | Подтяжка DATA и конденсатор — на модуле (`R`, `C`); J10-16 ещё и аппаратно подтянут вверх. Питать от 3.3 В, не 5 В |
| **TM1637** (4-Digit Display V1.2, HW-069) | CLK → **J10-17**, DIO → **J10-18**, VCC → **J9-17** (+3V3), GND → **J9-14** | GPIO2_B4 (2:12), GPIO2_B3 (2:11) | Порядок пинов — сверить с шелкографией модуля (обычно CLK·DIO·VCC·GND). От 3.3 В светит чуть тусклее |

Свободны для дальнейшего: J9-7, J9-12, J9-15, J9-16, J9-18, J9-22, J10-6, J10-8, J10-19, J10-20,
J10-15, J10-2, J10-4; J10-5/7 (если uart4 выключен). ADC: J9-26, J10-3 (≤ 1.8 В!). I2C1 (J9-3/5) — пусто.

## Что этим проверяется

| Модуль | Путь в pioneer | Фаза | Ожидаемый результат |
|---|---|---|---|
| UART-петля | `HW.uart` / `UART("uart3")` в SDK; ноды «UART: чтение/запись» в проекте | сейчас | записанное читается обратно; при открытом другим процессом порте — понятная ошибка |
| TM1637 | нода «Дисплей TM1637» (драйвер в core, bit-bang по двум выходам, без RPC); в скриптах — bit-bang через SDK | сейчас / модуль (idea 001) | число на дисплее; нет NACK; кандидат в первую протокольную модель стенда (`seven_segment`) |
| DHT22 | ядерный драйвер `dht11` через DT-оверлей → iio (`in_temp_input`, `in_humidityrelative_input`) | фаза 3 (оверлеи) | после оверлея J10-16 — «занят драйвером ядра: dht…»; значения читаются; из userspace протокол не вытянуть (импульсы 26/70 мкс) |

## Тесты на железе (план)

`make test-board` — отдельный набор, запускается только при подключённой плате (`PIONEER_BOARD=root@…`):
UART-петля → TM1637 (вывод `8888` / счётчик, визуально) → позже DHT22.
Обычный `make test` по-прежнему идёт на виртуальном стенде.

## Результаты проверок

**2026-10-11** — скрипт «Проверка стенда: UART + TM1637» (в списке скриптов на плате):
- UART-петля ttyS3 @115200: 136 Б отправлено → 136 Б получено, совпадает. **PASS.**
- TM1637: вывод работает (`8888` → `PASS` → счётчик mm:ss с двоеточием); ACK не читается — на 9-м такте DIO держим в 0 сами.
- ⚠️ **Цена RPC из скрипта:** кадр TM1637 (~270 переключений линий) — **718 мс**, т.е. ≈ 2.6 мс на вызов worker → core.
  Для протокольных драйверов в Python-скриптах это узкое место (idea 001, открытый вопрос 5). Варианты:
  пакетная RPC-операция «последовательность уровней» (одним вызовом), драйвер модуля в core/HAL,
  либо прямой доступ worker'а к захваченной линии. Решить вместе с модулями.

**2026-10-11** — DHT22 (`tools/probe/dht22_probe.py`, без pioneer, gpiod напрямую):
- Подключение исправно: DATA в покое HIGH (подтяжка модуля), датчик отвечает на старт-импульс; длительности битов
  по даташиту: «0» ≈ 21–27 мкс, «1» ≈ 62–72 мкс. Лучшая попытка — 25.3 °C (по хвосту кадра).
- Из userspace на одной линии **ненадёжно**: переключение линии выход→вход (`reconfigure_lines`) на vendor-ядре
  занимает **1–1.7 мс** → теряются первые 10–20 бит из 40, контрольную сумму не проверить; плюс изредка
  склеиваются фронты (импульсы 180–420 мкс).
- ⚠️ **В ядре NapiLinux 0.3.1 нет драйвера `dht11`** (`# CONFIG_DHT11 is not set`, модуля нет) — путь
  «оверлей + ядерный драйвер» (idea 002 п.4) для DHT22 закрыт, пока драйвер не появится.
- Варианты: (1) вторая линия-слушатель — перемычка **J10-16 ↔ J10-15**: J10-15 заранее ловит фронты, J10-16 только
  даёт старт → полный кадр + проверка суммы + повтор; (2) собрать `dht11.ko` под 6.6.89 vendor;
  (3) попросить napilab включить `CONFIG_DHT11`.
